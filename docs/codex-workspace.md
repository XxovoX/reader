# 透明悬浮阅读（当前推荐模式）

本机已安装到 `/Applications/Reader Hover.app` 并注册到 macOS 应用列表，可在「应用程序」中搜索 **Reader Hover** 打开。后续本机构建更新也需同步这份应用包；书架数据仍使用当前开发数据目录，不随应用包移动而改变。

已按当前需求改为 **独立透明置顶文字层**：默认白色文字，鼠标进入区域显示、移开后隐藏，背景、标题栏、边框和工具栏均不显示。隐藏时鼠标事件穿透到下方 Codex，计时暂停；显示时按悬浮可见时间计时，即使 Codex 继续保持焦点也能记录。

## 缩放与字体验证（2026-11-11）

- macOS 实机：右边缘 620→520、下边缘 190→150；修复连续角落拖拽卡顿后，再验证右下角 371×179→331×149、左上角→311×139，最后放大回 620×190。重开窗口恢复保存的 371×179，尺寸持久化有效。
- 渲染检查使用本地 Vite + 独立无头 Chrome（当前会话无 Browser 技能），注入测试正文，覆盖 800×300 和 280×90；八个边角拖拽区域与光标、系统字体 19.2px、白色正文、字号增大与恢复均验证通过，无页面运行错误。浏览器检查不代替原生缩放验证。
- 实机多显示器跨屏仍未测试；坐标已统一到逻辑像素，避免主屏与副屏缩放不同导致鼠标位移换算不一致。

## 计时规则（2026-11-11 修订）

- 悬浮正文显示时计时，移开鼠标隐藏后暂停；Codex 保留键盘焦点不影响计时。文档真正隐藏时也暂停。
- 使用单调时钟计算实际经过时间，系统时间调整不会多算；每本书分别保留不足一秒的余数，移入/移出、换书及重启不会逐次四舍五入。
- 显示期间约每 5 秒保存，隐藏、离开页面及返回书架时结算。数据库按完整秒累计，毫秒余数继续保留。
- 已结算但提交失败的记录保留在本机队列；重开应用会补交，同一事件只入库一次。
- 鼠标边界由原生窗口每约 40 毫秒采样，不承诺逐毫秒的边界精度。强制杀进程可能丢失最后约 5 秒尚未结算的时间；锁屏/睡眠情景尚未实机验证。

本次验证：前端 90 个文件、1,226 项测试通过；Rust 库 603 项通过、4 项忽略。覆盖反复短暂显示、隐藏停表、焦点变化、系统时间调整、换书归属、重开补交、失败重试和事务去重。 实机由用户确认白字显示；本次操作入库新增 7 秒，随后移开约 68 秒数据库保持 89 秒不变。该次停留未经秒表测量，不作为“显示恰好 10 秒”的精度证据。

## 启动桌面版

在 Reader 原书架的书籍卡片上点「悬浮阅读」。主窗口会隐藏，在上次保存的位置和尺寸显示透明阅读区域（首次打开居中）；结束后主窗口回到 Reader 原书架。桌面版不需要先进入独立的工作区页面。

- 鼠标移入该区域：显示白色正文。
- 鼠标移开：文字隐藏，不留按钮或占位面板。
- 滚轮：正常上下滚动正文，滚到章节末尾后继续向下滚进入下一章；向上同理。触控板也支持滚动。
- 拖动四条边：分别调整宽度或高度；拖动四个角：同时调整宽高。靠近边缘显示缩放鼠标和细提示，离开后不保留边框。最小 280×90，自动保存尺寸，重新开窗或重启软件恢复。
- 按住 **Option 拖动**：移动悬浮区域，位置也会自动保存；返回书架和退出软件时会补存最后一次变化。
- 右键：调整字号、切换深浅文字、跳章或返回书架；平时不显示这些控件。
- 网页模式继续用于管理；真正透明覆盖其他应用需要启动原生桌面版。

默认文字是 `#ffffff`，系统字体栈与 Codex 桌面版一致（`-apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif`）。按当前 Codex 正文 16px、窗口 120% 缩放，匹配到悬浮窗 19.2px；常规字重 400、行高 1.625，相邻段落间距 1em（与当前 Codex 正文样式一致）。右键可以增减字号或「恢复 Codex 字体」。这是当前设置的匹配预设，未实现持续读取 Codex 的字体/缩放设置。浅色背景上白字对比度低，适合覆盖 Codex 深色区域；也可以右键切换深色文字。

这个窗口当前是系统置顶层，可以手动放在 Codex 上方；**尚未实现绑定 Codex 窗口、跟随其移动或只在 Codex 前台时显示**。透明区域的位置和大小自动保存到数据目录的 `hover-window.json`，字号与文字颜色也会保留。拔掉显示器导致保存位置落在屏幕外时，恢复到当前屏幕并限制尺寸；旧版只有尺寸的文件仍可读取，首次使用新版本时居中。全屏应用/多显示器场景仍需实机补充验证。

交互参考：[Thief 官方小说模式文档](https://thief.im/help/use/use1.html)，其中明确提供鼠标移开隐藏、移入恢复，以及滚轮阅读。当前实现延续此交互，但继续复用 Reader 的章节、进度与 WebDAV 同步。

本轮已由用户在 macOS 上确认：**能看到白字，滚轮可用**。前端 1,215 项测试通过；Rust 库 601 项通过、4 项忽略；前端生产构建通过。此前进度同步和时长合并的配置方式见下文。

# Reader 内集成说明

基于 hadc188/reader v1.6.5，Fork：https://github.com/XxovoX/reader。
目标手机版本：开源阅读 **3.22.031722**。

## 启动

需要 Node.js、Rust 与 macOS Xcode 命令行工具。首次：

```sh
cd frontend
npm ci
npm run build
cd ..
cargo run --example workspace_server -j 4 -- ../work/reader-data 1122
```

本仓库也提供 `./scripts/start-workspace.sh`，可识别本次在 `../work/runtime` 安装的 Rust。

在 Codex 的浏览器面板打开 `http://127.0.0.1:1122/#/workspace`。阅读内容是本地网页，显示在 Codex 面板中；不会写入聊天消息，也不需要把正文发送给模型。后端需保持运行。

数据保存在指定的目录中，与应用包和 Git 仓库分离。请备份整个数据目录，尤其是数据库、书籍和 `legado-mac-device-id`；丢失设备 ID 会让后续合并被视作新设备。

## 阅读与进度

- TXT / EPUB 与手机在线书架、书源导入都在 Reader 原有书架/备份窗口操作。现有同地址条目保留，手机本地书正文需单独导入。
- 在「设置 → 备份与恢复 → WebDAV 网盘备份」配置 WebDAV 地址、账号、应用密码和目录，并开启「同步阅读进度」。手机端也需开启进度同步。
- 阅读页使用系统字体、白底灰黑文字，隐藏封面和章节大标题。目录、同步和返回入口在顶栏。
- 开书时读取云端进度；阅读期间每 30 秒同步一次，退出时保存。同步比较章节和章内位置，优先采用更靠后的进度，**不支持自动把另一端回退到更早章节**。两端需使用同一书源/目录；不同排版的字符位置存在近似。
- `Esc` /「隐藏」立即遮住正文和目录、停止朗读与自动滚动、暂停计时。「继续」恢复。刷新隐藏页也保持遮挡。快捷键需焦点位于阅读网页内，无法拦截 Codex 外壳先行处理的全局快捷键，故保留可点击的隐藏按钮。
- 切换窗口或浏览器页面不计阅读时长。每 30 秒、隐藏、失焦及退出结算到本机数据库。
- 新增备份与 WebDAV 管理接口只在本机监听模式开启，局域网模式不可用；不提供公网访问部署。

## 将 Mac 时长合并到手机

这不是手机原生的时长导入按钮，也不是自动云端时长同步。流程是生成一份修改过的**完整手机备份**，再由手机恢复。

1. 在手机结束阅读并退出阅读页，让手机时长结算。生成最新完整备份。此版本的 WebDAV 备份为 `backupYYYY-MM-DD.zip`，可从网盘下载到 Mac；如果本地备份是文件夹，应将里面的文件平铺打包（`bookshelf.json` 等直接位于 ZIP 根目录）。
2. Reader「设置 → 备份与恢复 → WebDAV 网盘备份 → 合并 Mac 阅读时长到手机」选择 ZIP。
3. 下载新生成的 `backup-mac-日期时间.zip`，原备份不会修改。保存原件。
4. 将新文件放到手机同一 WebDAV 的备份目录中，然后在手机 WebDAV 恢复列表选择它。旧版的本地恢复主要接收文件夹；若用本地恢复，先将 ZIP 解压，再选择包含备份文件的目录。
5. 恢复后检查阅读记录。**完整恢复也会恢复备份当时的书架和设置**，因此从备份到恢复期间尽量不要继续在手机改设置/阅读。每次合并都必须重新获取最新手机备份。

同一 Mac 重复合并同一份最新数据不会重复增加时长；累计时长重置时不会从手机扣减。请勿把本机已从别处导入过的统计再次当作新增 Mac 时长合并。手机统计按书名聚合，同名不同作者会合在一起（旧版手机自身的规则）。本功能只合并总时长/按书时长，不重建手机不存在的每日会话历史。

### 为什么针对旧版做特殊处理

已核对 tag `3.22.031722`（commit `fcc1e8b741b283efbddafd020f823f4a57da920b`）的源码：

- `ReadRecord` 主键是 `(deviceId, bookName)`，`readTime` 为毫秒。
- `Restore.restoreDatabase` 对其他设备记录执行 REPLACE，当前 Android ID 记录仅取较大值。
- **该版 `ReadBook.resetData` 读取按书 SUM 的总时间，`upReadTime` 写回默认 `deviceId=""`**。直接新增正时长 Mac 设备行会在手机下一次读书时重复累计。
- 因此只把尚未合并的 Mac 增量加到默认设备记录，并生成 `reader-mac-UUID@累计毫秒`、`readTime=0` 的标记记录。标记随手机恢复/备份保留，但不参与时长总和。再次合并读取最大标记，仅添加新增差值。不要手动删除这些标记。
